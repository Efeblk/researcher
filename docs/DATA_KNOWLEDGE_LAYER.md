# Deterministic data and knowledge layer

This Analysis Service layer keeps SQL Server authoritative and does not call an analysis model. It adds three bounded capabilities: publication-metrics policy and provider consistency, faculty evidence retrieval, and a Neo4j-ready public evidence projection. All persistent product endpoints run at `/api/v1/...`, authorize the requested subject before any product data read, and pass the authorization grant's subject identifier to the workflow. Collector source tables are accessed only through private read-only source models. Runnable search, reference-population, and graph requests are in [AcademicKnowledge.http](../ResearcherAnalysisService/Requests/AcademicKnowledge.http).

## Publication metrics V4

`publication-metrics-v4` retains all V3 counts, provider-specific blocks, provenance, conflicts, and coverage. Its descriptive eligibility policy includes every collected `AcademicWorkCategory`; that inclusion does not make a category eligible for ranking, HR evaluation, or field normalization. Provider profile totals remain separate and are excluded from evaluated outputs.

The cross-provider block compares only current observations owned by the requested researcher and joined through the same canonical work. Each provider is resolved independently. It reports DOI-overlap denominators, missing/conflicting values, exact year/category/citation-count agreement, and citation-count absolute differences. Agreement means saved-data consistency. It does not establish truth, equivalent coverage, or provider interchangeability, and values are never merged.

`/api/v1/knowledge/reference-population/import` stores an immutable manifest, its server-computed content fingerprint, provenance, cohort and sampling definitions, eligibility-policy version, review attestation, and typed members. `/api/v1/knowledge/reference-population` provides a guarded readback by manifest version. Migration `202609120002` adds `analysis.ReferencePopulationManifests` and `analysis.ReferencePopulationMembers`. Import validation checks bounds, unique member identities, recognized category names, years, nonnegative citation counts, and content identity. A review attestation is reported separately from scientific validity. `ReadyForInternalNormalization` remains false because no compatible execution formula or approved active catalog policy exists. Publication metrics therefore continue to return a null internal normalized score.

## Faculty evidence search

`/api/v1/knowledge/search` performs bounded lexical retrieval over immutable spans from the latest saved canonical analysis for each work and language. The corpus is restricted to works with a current association to the authorized subject. A latest run whose source snapshot belongs to another work is rejected without falling back to an older run. The request accepts a query, up to 100 optional canonical-work IDs, and `Take` from 1 through 20. It makes no provider or model call.

The pinned `academic-evidence-search-v4` catalog keeps direct lexical matching and the saved-claim bridge. It normalizes Turkish case and diacritics, including `I/ı/İ/i`, and scores whole tokens and phrase boundaries. Deterministic bounded Turkish suffix recognition detects query intents, and each detected intent adds a bounded set of English source terms to the SQL candidate search. Conditions also request finding context. Diversification selects the best exact phrase first. For explicit multi-work filters, it then attempts a verified saved-claim section match for each selected work and detected general intent before falling back to direct intent text and the global ranking. A condition or limitation slot is eligible only when the span contains explicit condition or limitation evidence. A summary section label alone cannot fill those specialized slots; lexical markers remain heuristic.

The bridge may match query terms against retained claims from `automatically_checked` latest runs, but follows every match back to the exact linked source span. Claim, run, snapshot, work, and current-owner association must agree. Duplicate claim links do not duplicate a span or multiply its rank. Direct exact-source phrases rank above intent-only matches. Retrieval still uses the same authorized-person corpus and optional canonical-work filter; query expansion does not widen either scope.

The response records additive `source_text`, `source_text_intent`, `summary_claim`, and `summary_section` provenance. For `source_text_intent`, `Section` names the matched lexical intent; it does not prove an article section or the truth of a fact. Claim provenance includes the actual claim ID, analysis-run ID, language, and section, while returned evidence remains only the immutable original span. Separate bridge run/work/language coverage, candidate counts, and truncation accompany the direct-span metadata. `QueryHash` identifies the normalized original query. `QueryPlanHash` additionally pins the catalog version, normalized ranking and database tokens, detected intents, bounded English source terms, and section intents. `CorpusHash` identifies the selected latest source runs, while `ClaimBridgeHash` identifies the bounded query candidate claims and valid links, including claim text and exact span identity. `InputHash` covers these identities and request bounds. Older saved manifests remain readable with later catalog metadata absent.

This is bounded saved-claim and deterministic-intent-assisted lexical retrieval with zero AI calls. It does not provide general semantic search, translation, exhaustive recall, or general morphology. English source-intent expansion is a fixed nonsemantic vocabulary, and Turkish suffix recognition is bounded. A query can miss when no Turkish summary exists, verification did not retain the relevant claim, claim selection omitted it, wording falls outside the catalog, or the coarse SQL candidate cap is reached before in-memory whole-token scoring. Claim paraphrases are search hints only and never become evidence or model input. `AnalysisLanguage` is the saved analysis request language and does not detect the quoted source language. `SourceId` remains document-local; consumers cite the globally scoped `EvidenceId` (`work:{id}:snapshot:{id}:span:{id}`).

Downstream faculty generation records its own typed provider-attempt provenance separately from this deterministic
retrieval plan. An output-limit recovery does not change `Query`, `QueryHash`, `QueryPlanHash`, selected evidence, or
corpus scope: the second request receives the same pinned query and evidence. Retrieval provenance therefore remains
stable even when the bounded generation path uses a second attempt.

Synthetic SQL fixtures cover direct lexical retrieval, Turkish claim-to-English-span bridging, section intent, malformed and unauthorized links, deterministic hashes, deduplication, and bounded truncation. The existing labelled calculation fixture obtains recall `1.0` and MRR `0.5` at `k=20`; these values verify calculation and identity plumbing only. They are not representative retrieval-quality estimates. A representative labelled faculty-query set is still needed before making production recall or ranking claims.

## Derived graph projection

`/api/v1/knowledge/graph/export` accepts exactly 20–50 canonical works associated with the authorized subject. The export selects only canonical identities, latest saved analysis runs, immutable source snapshots and spans, claims, and exact claim-to-span evidence. Per-type property allowlists prevent researcher, personnel, faculty, department, authorization actor, and HR fields from entering the bundle.

Nodes and relationships are sorted and hashed. Stable SQL IDs, analysis policy versions, source hashes, extraction versions, and exact evidence links make rebuilds reproducible. Returned Cypher uses parameters only, scopes node identity by both `projectionId` and node ID, and deletes only nodes with the selected projection namespace. Proposed relationships remain `PendingEvidenceValidation`; the presence of an evidence ID does not establish that a span supports a relationship.

The offline 20-work fixture traverses the exported `CITES_EVIDENCE` edges and obtains exact set agreement `1.0` against the authoritative SQL query. The local Docker engine and `cypher-shell` are unavailable, so actual Neo4j execution, latency, operational complexity, model/provider cost, and adoption benefit are `NotRun`. SQL retrieval remains the production baseline until a later controlled graph trial demonstrates a measured benefit without weakening authorization, evidence, deletion, or auditability.
